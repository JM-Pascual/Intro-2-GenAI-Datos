¿Por qué no solo bytes?

  • Las redes necesitan secuencias lineales de símbolos discretos
  • 256 bytes posibles son muy pocos — necesitamos más expresividad
  • Los IDs son solo etiquetas únicas — sin semántica intrínseca
  • Más símbolos → secuencias más cortas → contexto más eficiente

Pre-training

Byte Pair Encoding

El algoritmo que expande 256 bytes hasta un vocabulario de 100k+ tokens expresivos

  • Empezamos con 256 símbolos (todos los bytes posibles)
  • Encontramos el par de tokens más frecuente en el corpus
  • Lo fusionamos en un nuevo token con ID propio
  • Repetimos N veces — GPT-4 realiza ~50,000 merges
  • Nos detenemos cuando el vocabulario alcanza el tamaño objetivo

Pre-training

Entrenamiento de la Red

Predecir el siguiente token — repetido miles de millones de veces, en paralelo

VENTANA DE CONTEXTO
Input
Target
  • Tomamos ventanas de longitud variable — de 0 tokens hasta el tamaño de la ventana de contexto
  • Ventana más larga → mayor capacidad de contexto, mayor complejidad
  • Salida: 1 neurona por token del vocabulario y la probabilidad de que ese token sea el siguiente
  • Al inicio los pesos son aleatorios
  • Sabemos la respuesta correcta: el token que seguía en el corpus
  • Actualizamos los pesos para que la probabilidad del token correcto sea cada vez mayor
  • Todo ocurre en paralelo, en grandes batches, sobre todo el dataset
CONTEXT WINDOW
La cantidad de tokens ingestados por la red en cada paso de entrenamiento
$P(\text{token} \mid \text{contexto})$
OBJETIVO DEL ENTRENAMIENTO
Actualizar los pesos para maximizar la probabilidad del token correcto:
maximizar $P(\text{token correcto} \mid \text{contexto})$

Inferencia

Generación de texto token a token — un proceso estocástico

  • Se genera de a un token a la vez
  • Cada token generado se agrega al contexto para la próxima predicción
  • Proceso estocástico: el output varía entre ejecuciones
  • El texto está inspirado en training, no lo copia — es regurgitación cuando sí lo hace

Post-training / SFT

  

    
Supervised Fine-Tuning

    
Enseñarle al modelo cómo comportarse — creando un dataset de conversaciones humanas

    

      

        
    
          
  • Dataset de conversaciones creadas por labelers humanos
    • 
          
  • Labelers siguen consignas para garantizar calidad y consistencia
    • 
          
  • El modelo cruza su conocimiento base con el cómo comportarse
    • 
          
  • Los LLMs están, probabilísticamente, imitando a los labelers que armaron el dataset

Post-training / SFT

  

    
Alucinaciones

    
Cuando el modelo responde con confianza algo que no sabe

    

      

        
El Problema

        
    
          
  • El modelo responde con confianza información incorrecta o inventada
    • 
          
  • Viene del post-training: se refuerza un estilo seguro y confiado
    • 
          
  • También: respuestas correctas pero fuera de contexto
    • 
        

        

        
Vague Recollection vs Working Memory

        
    
          
  • Vague recollection → lo que el modelo recuerda de sus pesos
    • 
          
  • Working memory → información en la ventana de contexto
    • 
          
  • La ventana de contexto siempre gana — es más confiable
    • 
        

      

      

        

          
MITIGACIÓN 1 — Dataset "No sé" (Meta LLaMA 3)

          

            Un LLM genera preguntas desde textos → el modelo base las responde → si no sabe, se crea un ejemplo de training donde la respuesta correcta es "No sé"
          

        

        

          
TAKE-AWAY

          
Lo que está en la ventana de contexto siempre es más confiable que lo que el modelo "recuerda" de sus pesos

        

      

    

  







  
Post-training / SFT

  

    
Tool Calling

    
El modelo puede pausar la inferencia y llamar a herramientas externas para obtener información real

    

      

        
    
          
  • El modelo emite tokens especiales que señalan una llamada a herramienta
    • 
          
  • La inferencia se pausa — el sistema ejecuta la búsqueda o función
    • 
          
  • Los resultados se insertan en el contexto y la inferencia continúa
    • 
          
  • Se entrena al modelo cuándo llamar herramientas con ejemplos en el dataset de SFT
    • 
        

        

          
¿POR QUÉ IMPORTA?

          
Convierte los LLMs de almacenes de conocimiento estático en agentes capaces de actuar sobre el mundo real

        

      

      

        
FLUJO DE EJECUCIÓN

        

          
TOKENS DE CONTROL

          
<Search_Start>capital of France<Search_End>

          
Tokens especiales señalan al sistema que debe pausar y ejecutar la búsqueda

        

        

          
RESULTADO INSERTADO EN CONTEXTO

          
<Search_Result>Paris is the capital...</Search_Result>

          
La respuesta real se inyecta en la ventana de contexto — la inferencia se reanuda con información factual

        

      

    

  







  
Post-training / SFT

  

    
Models Need Tokens to Think

    
Cada token generado activa un forward pass completo — ese es el "pensamiento"

    

      

        
    
          
  • Cada token generado desencadena recomputación completa del contexto
    • 
          
  • Obligar al modelo a responder de inmediato = predecir sin pensar
    • 
          
  • Tokens intermedios le permiten construir la respuesta en pasos
    • 
          
  • Los modelos no ven caracteres — ven tokens. Son malos contando cosas.
    • 
        

        

          
Conclusión: hay que darle al modelo problemas en los que es bueno.

¿Contar? → que escriba código.
¿Cuentas? → que escriba la ecuación primero.

        

      

      

        
COMPARACIÓN

        

          
✗ MAL PROMPTING

          
"¿Cuánto es 17×23?
La respuesta es ___"

          
Obliga al modelo a predecir la respuesta en un solo token

        

        

          
✓ BUEN PROMPTING

          
"¿Cuánto es 17×23?
Pensá paso a paso."

          
Genera tokens intermedios → la respuesta se construye naturalmente

        

      

    

  







  
Reinforcement Learning

  

    
Reinforcement Learning

    
El modelo descubre su propia forma óptima de razonar — más allá de imitar humanos

    

      

        
01
Generar N respuestas
Para el mismo prompt, el modelo genera múltiples respuestas posibles

        
02
Evaluar y filtrar
Respuestas incorrectas → descartar, correctas → guardar

        
03
Seleccionar la mejor
De las correctas, se elige la mejor por largo en tokens y calidad del razonamiento

        
04
Entrenar sobre el resultado
El modelo se actualiza para favorecer esa secuencia de tokens

Reinforcement Learning

  

    
RLHF — Reinforcement Learning from Human Feedback

    
No podemos clasificar todo manualmente — entrenamos una red que simule el juicio humano

    

      

        
    
          
  • Imposible clasificar todas las respuestas manualmente
    • 
          
  • Solución: entrenar un reward model que simule el scoring humano
    • 
          
  • A medida que se refina, mejor predice el label del humano
    • 
          
  • Este reward model se usa como señal para el loop de RL
    • 
        

        

          
THINKING MODELS

          
Model Distillation Risk: los providers muestran solo resúmenes del razonamiento para evitar que se destile a otro modelo

        

      

      

        
EL LOOP RLHF

        
01
Humanos rankean respuestas
Pares de respuestas son rankeadas por calidad

        
02
Reward model aprende
Una red neuronal aprende a predecir el ranking humano

        
03
Comparar rankings
Se mide la diferencia entre el ranking humano y el artificial

        
04
Usar como señal de reward
El reward model guía el entrenamiento de RL a escala
